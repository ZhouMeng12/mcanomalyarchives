# 渐进式架构优化计划

状态：前四轮和 PR 自检发现的两项修复都已实施，135 个 Java 测试、115 项守卫全部通过，
原来失败的世界路径也已转绿。真人交互和客户端动画还没验证。
Git 里只有初始基线，没有提交、推送或建 PR。

## 已授权范围

- 把公共启动接线、网络注册和服务端生命周期收到一处。
- 梳理复杂玩法的状态管理，先从怪树和紫怪开始。
- 修复理智批量同步没人调度的问题。
- 校验客户端发来的奖励和阶段推进请求。
- 把客户端舒适度配置和服务端的世界破坏规则分开。
- 加能跑真实 Java 规则的测试，不再让 Python 里的公式副本和实现各走各的。

## 阶段

1. **基线**：初始化本地 Git，纳入源码、资源、MCreator 元素、工具和 Gradle Wrapper，
   排除构建产物、运行数据和解释器缓存。
2. **设计与接线**：写清各模块的职责、状态归谁管、怎么接入生成区，并明确生命周期。
3. **公共机制**：理智同步调度、网络权限、服务端配置，补回归验证。
4. **玩法模块**：规则不变的前提下收拢怪树和紫怪流程，调用方逐步迁过去。
5. **验收**：生成区守卫、真实逻辑测试、编译打包；游戏内和专用服务器的验证结果与限制也要记下来。

## 验收原则

- 每个阶段都有能单独审阅的 Git 差异，必要时可以退回初始提交。
- 只搬目录或加转发类，不算模块优化。
- 不擅自发布、推送，也不改异常设定和资源注册名。
- 没做完的阶段、没跑的验证，都明说。

## 第一轮（2026-10-06）

- 延迟队列搬到手写的 `runtime`，随服务器会话创建和关闭；主类留一个兼容委托。
- 玩家任务可以取消，退出或 Clone 时清理；执行时先确认原玩家还在线且存活。
- 理智同步每 5 tick 合并发一次，发送时才读权威值；登录和重生立即同步。
- 清理理智瞬态计数、对话/故事和延迟攻击的生命周期。
- JUnit 直接跑生产用的 Java 队列；守卫加了接入、兼容委托和构建测试检查。
- 这轮不动紫怪权限和完整状态机、怪树存档恢复、配置拆分，留给后面几轮。

## 第二轮（2026-10-06）

- 服务端会话集中保存所属玩家、维度、演员 UUID/ID、阶段和抚摸计时。
- 自然触发、调试命令、网络请求和转场都走同一个模块。
- 只有第五阶段能结算触手；结算时先消耗会话，重复请求不会二次执行。
- 退出、死亡、Clone、切维度、演员失效和停服，都只清理所属会话。
- 七种客户端请求和三种客户端通知按方向统一注册，协议版本 `purple-story-2`。
- 客户端演出的取消共用一个清理入口；低 TPS 下，抚摸完成请求要等服务端确认。
- 旧包字段、注册名、剧情台词和 5/20/60 tick 转场都保留。
  客户端和服务器必须用同一轮构建，不能混用旧紫怪协议。

## 第三轮（2026-10-06）

- 怪树的阶段、目标、原基座和树身快照，归同一条实体恢复记录管。
- 阶段按实体已加载的 tick 推进，不再排延迟回调，所以卸载后不会留下捕获着世界的动作。
- 清树之前先存快照；重载时取消没打完的袭击，等相关区块加载后还原到原位。
- 迁居失败会回滚树身；平移以原来的脚底为锚点，自定义树冠不再被当成地面。
- 玩家的砍树计数按维度隔离，已经计过的树干不再重复遍历连通簇，离场时清掉坐标集合。
- 旧的三个玩法 Handler 已被新模块取代，结构补实体的入口保留。
- 未知、损坏或跨维度的记录会保留并隔离；旧版本已经丢了的方块快照，不会凭空重建。

## 第四轮（2026-10-06）

- 客户端舒适度只保留震动和眨眼；陨石与黑吸伪云的地形规则移到 SERVER 配置。
- 对照 NeoForge 21.1.190 的全局默认和世界覆盖规则，不假设 SERVER 配置会自动给每个世界建文件。
- 本地首次升级时，旧设置先备份再迁移，且不覆盖已有文件；专服不读客户端偏好。
- 旧的时长自检改成真正的 JUnit 入口，顺带改了公式注释；极端整数和时间差不再溢出。
- 现有的默认破坏开关和正常时长数值不变；服务端配置还没加载时，禁止破坏地形。
- 记下了 NightConfig 相对路径的原子写入问题，复验时改用独立的绝对 worlds 根。
