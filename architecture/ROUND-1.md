# 第一轮：理智同步与服务端任务生命周期

日期：2026-10-06。基线：`0cd5406` / `pre-architecture-refactor`。

## 做了什么

- 手写了服务器会话队列，原来的调用入口照旧能用；服务器停止后回调会被释放，不会带到下一个服务器。
- 任务可以取消。玩家退出或 Clone 时自动取消，执行前还会核对玩家身份。
- 理智模块自己调度：每 5 tick 合并发送，立即同步会淘汰旧的待发记录。
- 登录和重生的同步，从别的业务事件里挪进了理智模块。
- 清理了理智瞬态计数、故事的继续与超时、气泡续播和延迟攻击。
- 故事停止后会取消继续和超时任务，并用会话标识挡住旧回调，防止它推进新的故事。
- 加了真实 Java 单元测试，以及生成区和生命周期的守卫。

## 验证

- 改动前 `gradlew.bat build` 能过，当时工程里没有任何 Java 单元测试。
- 第一次迁移后，`gradlew.bat test build` 通过，17 个 JUnit 测试全过。
- 补上 Clone 接入后，离线跑 `gradlew.bat test build --console=plain --offline` 仍然通过：
  17 个测试（任务 10、理智 7），0 失败、0 错误。
- 80 项生成区和生命周期守卫通过。
- 小伪云、红伪云、黑吸伪云、名称解析、生物性质这 5 个原有离线自检全部通过。
- 在隔离副本里模拟 MCreator 覆盖兼容方法：守卫查出 2 项漂移，`apply` 恢复后 80 项全过，
  主类的 SHA-256 与模拟前一致。这个操作没碰实际工程。
- canonical 里新增了兼容方法的快照，原有的 canonical 文件没变。
- 这一轮结束时，客户端和专用服务器都还没真正启动过，在线重生、退出、换存档也没试，
  所以单元测试和编译通过，不能当成游戏行为已经验证。
- 第二轮补做了开发专服的空服启停，并确认本轮的任务和理智模块拿到的是正确的服务器实例，
  详见 `ROUND-2.md`。当时没有在线玩家，重生、退出、换存档的交互仍然没测。
