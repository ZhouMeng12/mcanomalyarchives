# 第八轮：钓竿、剧情运行时与回归守卫加固

日期：2026-11-01。改动前基线：`1b0e7d3`。

本轮处理稳定性、缓存生命周期和错误边界。异常事件概率、伤害数值和爆炸强度沿用当前设置。

## 已修复

| 位置 | 原问题 | 修复后的行为 |
| --- | --- | --- |
| 异常钓竿计时 | 遍历全部整数成员，以当前值在 10～1200 内猜测计时字段；可能误写其他状态 | 使用 Mixin accessor 精确访问 Minecraft 1.21.1 的 `timeUntilLured`，移除猜字段与字段转储 |
| 抛竿延迟任务 | 回调执行时再取 `player.fishing`，快速收杆重抛会串到另一只鱼钩 | 绑定本次鱼钩和世界，按玩家归属排队；退出、重生、换维度或重新抛竿后不误改新鱼钩 |
| 钓鱼结算 | 在确认服务端世界之前取消原版事件；生物注册名失效时可能取得默认实体 | 先检查服务端和同一世界，使用注册表 Optional 查询；无效条目不生成其他默认实体 |
| 虚空事件 | 世界最低高度硬编码成 -64 | 使用实际维度的最低建造高度；主世界默认高度下行为相同 |
| 剧情跳转 | 连续 `JUMP` 递归执行，自跳转或多个段落互跳会栈溢出 | `StoryCursor` 迭代推进，检测本次连续执行内的重复位置，并限制连续节点数；台词/等待/选项可以正常跨 tick 继续 |
| 空选项 | 空选项返回后仍保留运行状态，玩家无法重新开剧情 | 记录日志并继续后续节点 |
| 剧情缓存 | 普通读取反复访问磁盘；未修改覆盖文件每轮都重解析；缓存跨服务器会话残留 | `StoryRepository` 缓存解析结果，每 200 tick 检查修改时间与文件大小；开始/停止服务器均清空缓存 |
| 剧情覆盖文件 | 删除 config 覆盖后周期检查不会回退；手动 reload 可能沿用旧时间戳缓存 | 删除后重新加载数据包/内置版本；手动 reload 强制读取；无效编辑保留最后可用脚本，无旧缓存时尝试内置版 |
| 剧情名称 | 未验证名称就拼接文件路径和资源路径 | 仅接受资源名兼容的直接子文件名，拒绝目录越界、冒号和不合法名称 |
| 动画网络包 | 直接把实体 ID 查询结果强转成 Player，ID 复用成其他实体可能导致断线 | 先检查实际实体类型，不合适的目标直接忽略 |
| 生成区守卫 | `anomaly-feedback-files` 的列表字段误写成 `paths`，原实现把空检查当成通过 | 修正为 `exists`；缺失或空的 exists 列表也明确失败；添加隔离目录中的负面自检 |

钓竿原有等待公式仍为 `40 + floor(min(distance / 15, 1) × [200,599])` tick，延迟设置仍为 5 tick。准确访问字段后，原本被猜字段失败掩盖的等待规则现在能可靠生效，需要在实际客户端确认抛竿手感。

生成物品类只保留 `StrangeRodCasting.onCast` 接线，实际会话逻辑放入手写模块。新增物品类快照、Mixin 注册和网络类型检查的守卫。

## 后续建议

1. **钓竿大爆炸的单 tick 峰值。** 半径 50 的清除扫描会在一次事件内访问约 52 万个球内位置，之后还执行两次大爆炸。建议独立设计分批方块修改与邻居更新策略，并先确认是否允许清除过程跨 tick；这可能改变玩家看到的时序。
2. **命名牌吸收上限。** 当前仅在每列/每件掉落物之前检查总上限；一列里的多个材料块、容器中的整叠物品仍可能被全部清空。掉落物又按单件点数记账却删除整叠。需要按剩余额度统一扣取，修复会影响实际资源损失量，应先确认规则再实施。
3. **跨维来物实体接入。** 上轮的八套模型与贴图已经进入资源包，但新生物的实体注册、渲染器、钓获池和专属 AI 仍待接入；资源存在不代表已能在世界中生成。
4. **发布前游戏验证。** 优先覆盖快速抛竿/收竿、多人换维度、脚本热修改/删除、异常循环脚本以及中途加入客户端的动画包处理。
