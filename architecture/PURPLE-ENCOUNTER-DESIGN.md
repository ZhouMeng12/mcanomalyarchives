# 紫怪遭遇设计与缺陷审查

日期：2026-11-14。状态：主要流程与审查修复已实现，见末尾实施记录；实机验收待执行。
参考：正篇 BV1cJwCzjEma、雨夜窥窗补充篇 BV1ZkDfBxERN 的关键画面。
以下数值、事件调度、失败恢复属于游戏改编方案，不声称是视频原设定。

## 1. 体验与事件链

主链：脆弱时遭遇 → 回答诱导 → 接近紫狗 → 身体异变 → 同化完成 → 低频、逐渐靠近的窥视。
保留现有对话分支；提前拒绝可以退出，不能把所有拒绝都改成处决。
仅现有第四阶段危险回答进入处决支线。

### 首次遭遇与同化

- 暂保留现有低理智/低血量且静止的入口，开场前确认玩家存活、非创造/旁观、没有其他紫怪演出。
- 同化阶段：未接触、已回应、接触异变、完成。前两阶段随本次会话结束清除；完成阶段保存。
- 已回应：短促杂音、紫怪自身外观变化；接触异变：第一人称手臂及第三人称玩家渲染叠加紫色，从手向身体扩展，不修改真实皮肤文件。
- 最后确认才提交持久状态和一次性奖励；完成后自然入口不再重播初见，不靠重复初见刷奖励。
- 玩家死亡后保留完成状态和遭遇次数，这是本方案的明确设计选择；临时演出全部取消。
- 持久状态在登录、重生、换维度和开始追踪玩家时同步。旁观者能看到身体变化，但不收到当事人的内心声音或界面。
- 紫狗站位先验证实际碰撞箱、走近路线和退路。无路时调整狗的位置；演出中被堵则取消，不让玩家穿墙或无限原地行走。

### 逐渐靠近与真正窥窗

- 完成同化后，先留至少 3 分钟安静期。初始可调冷却 3～6 分钟，每次结束后重新计时，重登不立刻补刷。
- 事件按已成功看见的遭遇推进：远处树边（约 24～32 格）→ 树后/视野边缘（16～24 格）→ 合适窗外（依实际窗位，约 4～12 格）。
- 雨夜提高窗外事件权重，但不是唯一触发条件。找不到合适窗户就推迟或改成远处事件，不能为了出现而塞进室内。
- 窗位需满足：玻璃两侧分别容纳玩家与紫怪；眼睛能通过玻璃对视；完整实体碰撞箱可容纳且有支撑；不在流体中；不穿过另一堵墙。仅检查附近已加载区块。
- 视线允许穿过普通透明玻璃/玻璃板；实墙和遮挡物仍阻断；着色玻璃是否允许应单独配置。使用有限长度、有限次数的射线检测，避免跳过玻璃后顺带穿墙。
- 在所有附近生存玩家都没看着候选位置时出现。出现后跟随目标转头，不追着玩家跑。
- 连续直视约 0.3 秒后记一次发现，停留 1～2 秒再消失；一次掠过不立即触发。任何有效观察者都可使其退去，但遭遇进度只归属本次目标。
- 全服一个窥视者的现有限制暂保留；用轮转挑选合格玩家，避免固定遍历顺序偏向同一个人。
- 剧情会话和窥视互斥。攻击窥视者暂定快速收回/消失并进入冷却，不假装触发尚未实现的 Boss 战。

### 触肢处决

- 危险回答后进入服务端 EXECUTION 状态，拒绝再次选择、领奖或启动抚摸。
- 初始时间轴：0～10 tick 停顿并收紧视线；10～22 tick 触肢伸向当事人；22 tick 命中结算；22～36 tick 收回和退场。
- 动画附着于实际演员和目标位置，不用摄像机瞬移代替实体命中。旁观者也能看到触肢。
- 只结算一次伤害，不伤及围观玩家、不破坏地形。默认保留图腾和其他合法伤害保护；存活也正常结束演出，不补第二次强制死亡。
- 命中前重新校验同一会话、玩家身份、维度、距离和演员有效性。死亡、下线、换维度、切创造/旁观或演员消失立即取消，不遗留延迟杀伤。

## 2. 代码审查发现

### 高优先级：抚摸可能长期锁定控制

证据：`event/PurpleDogPettingClientHandler.java` 的 phase 2 / 4 只按水平距离推进，移动使用碰撞约束的 `player.move`，没有无进展或最大时长判断；找不到狗时也直接等待。`PurpleStoryModule.onTick` 校验演员身份和距离，但没有 PETTING 的截止时间。

复现条件：玩家走近或退回时被方块挡住，演员仍存活且在 16 格内。客户端可一直锁方向键和视角，服务端会话一直有效。

修复要求：移动连续 20 tick 无进展即取消；整个抚摸最多 200 tick；服务端独立超时并下发结束。取消不能丢物品或发奖励。临时丢失实体追踪包允许短暂宽限，但不能无限等。

### 中优先级：多人视线与进度归属错误

证据：`entity/PurpleMonsterEntity.java:217` 只取最近玩家，后续可见性、直视和 `countSighting` 都使用这个人，而生成时另有 `PurpleStalkerOwner`。

复现条件：A 是遭遇目标且正看紫怪，B 离紫怪更近却背对它。A 的直视不参与判定；若 B 发现它，进度又会记到 B 身上。

修复要求：所有有效观察者参与发现判定；目标 UUID 决定剧情进度，二者分开。创造/旁观不消费生存玩家的遭遇。

### 中优先级：窗位和玻璃视线不匹配

证据：`PurpleStalkerHandler.pickScenicSpawnPos/isScenicSpot` 只验证邻接玻璃/树木，不验证窗内外、眼高与透窗视线。`PurpleMonsterEntity` 则调用普通 `hasLineOfSight`。

确定缺口：当前不能保证生成在窗外。需游戏验证的风险：普通碰撞射线可能把玻璃当成阻挡，导致玩家隔窗看得见而程序认为看不见。

修复要求：专用窗位选择与透玻璃视线检测；测试透明玻璃、玻璃板、着色玻璃、两层窗、窗后实墙和低窗。

### 中优先级：同化后的初见重播与窥视可重叠

证据：自然入口仅检查当前剧情、冷却和脆弱/静止条件，没有排除已同化；窥视入口仅检查同化与共享窥视者，没有排除正在进行的剧情。

结果：冷却结束后可再次触发初见；已同化玩家进行自然或调试剧情时，可能额外生成窥视者。重复领奖是否原先有意允许不确定，但与本方案一次性同化冲突。

修复要求：统一遭遇调度；已完成玩家只进入后续事件；调试入口明确绕过哪些限制，调试不能污染正常奖励标记。

### 待实机验证：卸载中的剧情演员可能残留

证据：会话只存在内存；`discardActors` 只查找当前已加载实体；紫怪存档方法保存窥视状态，但不保存表演目标和表演模式。

风险路径：演员区块先卸载，随后会话清理无法找到演员，重新加载时无法识别它属于已经结束的演出。是否实际出现受卸载事件时序影响，不能当作已复现。

修复要求：剧情演员不作为普通持久实体恢复；持久标记记录“临时演员”，加载发现无有效会话即移除。演出取消不主动加载区块。

### 其他行为缺口

- `PurpleBossFightTrigger` 只记日志和冷却，调用者随后消失；这是占位功能，不能对玩家显示“Boss 战开始”。
- 现有处决为普通 mobAttack 的极大伤害后立即清演员；伤害被保护机制拦截时不会保证死亡。应按上述“允许合法保护”的规则明确语义。
- 同化和遭遇次数附件序列化了，但没有显式 `copyOnDeath`，项目中未发现它们的重生搬运代码；需验证重生保留，并按本方案补齐。
- 冷却注释与代码不符：窥视实际 600～2399 tick（约 30～120 秒），明处概率 0.8。属于调参/维护问题，不是崩溃缺陷。

## 3. 验证与实施顺序

本轮运行：`gradlew.bat test --tests '*anomaly.purple.*' --console=plain`，31 项通过，0 失败、0 错误。
覆盖现有会话顺序、演员身份校验、重复结算、取消清理与共享窥视占用。它们不覆盖真实碰撞、玻璃射线、网络延迟或动画观感。
环境不能启动 Minecraft；上面的复现条件是待实机执行的步骤，不声称已在游戏中重现。

实施顺序：

1. 修复抚摸超时、多人观察归属及剧情/窥视互斥，增加相应状态机回归测试。
2. 实现窗位选择和玻璃视线，验证单人、多人与不同窗户结构。
3. 加入同化阶段保存/同步、一次性奖励和重生规则。
4. 最后接触肢动画和服务端处决时间轴，验证图腾、重复请求、低 TPS、演出中下线/换维度/死亡/切模式。

验收底线：取消路径全都恢复输入和视角；不重复丢物品/发奖/伤害；不跨维度执行；无合法窗位时不硬刷；第三人称和多人看到的阶段一致。

## 4. 实施记录

- 抚摸增加客户端无进展 20 tick、丢失追踪 40 tick、总时长 200 tick 的退出；服务端独立执行 200 tick 上限，边界时刻的完成包不能抢领奖。取消走独立、带演员身份的请求，不误选最终同化分支。
- 生成紫狗及接受抚摸前检查直线去路、支撑与高度；遇到台阶/坑/墙会换候选站位或结束。途中地形变化由无进展退出兜底。
- 多人观察按每位观察者连续 6 tick 判断；无关近处玩家不遮蔽远处观察者。被发现后停留 40 tick，进度归目标玩家。
- 窗外候选检查眼高、玻璃交叉、双方站位、实际碰撞箱和露天/树冠条件；透普通及染色玻璃、玻璃板的视线保留后方实墙遮挡。遮光玻璃仍阻断。多层透明窗可通过检测。普通回退点也要求露天或仅被树冠覆盖，不把室内玻璃旁当窗外。
- 窥视间隔改为 3～6 分钟，冷却序列化并在结束后刷新；低光概率 1、亮处 0.2。至少发现 4 次后才尝试窗外事件，雨夜窗口权重 0.9，其他时候 0.5。没有合法位置就跳过。
- 剧情与全服共享窥视互斥，轮换玩家扫描起点。完成同化后不再自然重播初见。攻击窥视者使其退去，不调用 Boss 占位。
- 完成同化与遭遇次数保留至死亡重生；第一/第三人称使用实际玩家模型、原皮肤纹理的紫色叠加。抚摸后先手臂再身体渐变；取消恢复原状，已完成状态在登录、重生、切维度、开始追踪时同步。
- `/purplegui` 流程标记为预览，不发奖励、不写永久同化、不造成处决伤害。已有同化玩家的持久状态不受预览取消影响。
- 处决改为服务端 22 tick 单次命中、36 tick 结束；三条弯曲收尖触肢连接紫怪和实际目标。保留普通伤害保护，图腾生效后不追加杀伤；命中前死亡/下线/切维度会取消。处决自身造成的死亡允许剩余收回动画播放，重生仍立即清理。
- 剧情演员持久数据带临时标记；从磁盘重新载入时拒绝恢复已经不属于内存会话的表演实体，不主动加载区块找演员。
- 阶段一追踪包晚到时先等待，超时则同时取消服务端会话，不再只丢弃客户端过渡状态。

验证：新增抚摸阻塞/超时、多人连续观察、处决一次性/取消、调试不结算、过期完成包等回归用例。完整构建曾因共享目录中编译产物缺失报错，强制重新编译后完整构建通过；未修改其他模块来绕过测试。最终完整构建通过：264 项测试通过，其中紫怪专项 47 项（新增 16 项）；生成区守卫 241 项通过。
