# 架构优化工作区

这个目录放本次重构的计划、架构决策和验证记录，以及后续的本地待办。
不接外部 issue tracker，不配 Git 远程，也不会自动推送。

## 文件

- `PLAN.md`：分阶段的实施范围和验收条件。
- `BASELINE.md`：重构前的基线、验证范围和已知问题。
- `ROUND-1.md`：理智同步与服务器任务生命周期，含实施、验证和遗留项。
- `ROUND-2.md`：紫怪的服务端会话、权限和网络接线。
- `ROUND-3.md`：怪树的阶段状态、恢复快照，以及真实 NBT 和世界内的恢复验证。
- `ROUND-4.md`：配置归属、旧设置迁移、时长测试和部署注意事项。
- `PR-FIXES.md`：PR 前自检发现的两个问题，以及修复过程、失败测试和世界回归。
- `adr/0001-server-session-runtime.md`：第一轮的模块分工与生命周期决定。
- `adr/0002-server-authoritative-purple-story.md`：紫怪会话的状态和结算方式。
- `adr/0003-strange-tree-recovery-journal.md`：怪树的持久状态和重载恢复策略。
- `adr/0004-server-gameplay-config.md`：客户端偏好与服务端世界规则如何拆开。
- 后续本地待办放在 `issues/`。

## 工作原则

1. 动玩法代码之前，先把当前工程提交成 Git 基线。
2. 注册名、资源名和 MCreator 工作区一律不动，免得悄悄破坏存档兼容。
3. 生成区只放稳定的接线；规则、状态和生命周期都收进手写模块。
4. Bug 修复、权限修复和架构调整分开记录。检查通过不等于运行正确。
5. 每个阶段都要跑真实 Java 实现的测试、生成区守卫和构建。专用服务器与游戏内验证单独记录。
