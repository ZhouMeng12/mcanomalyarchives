# 第二轮：紫怪服务端会话与奖励权限

日期：2026-10-06。初始基线：`0cd5406` / `pre-architecture-refactor`。
第一轮未提交的改动原样保留，没有重置或覆盖。

## 做了什么

- 会话状态、所属维度、演员身份、转场和抚摸计时，统一放进 `anomaly/purple/`。
- 自然触发和 `/purplegui` 共用同一个生成入口；旧事件类只留兼容入口和表演免伤。
- 七个请求包只负责提交交互，不再直接发物品、切模型、写同化状态或删演员。
- 只有走到第五阶段的合格会话才能领奖，领取和清理一次性结算。
- 重复转换不会重置或复制演员，重复的抚摸完成也不会多丢一次主手物品。
- 退出、死亡、Clone、换维度、停服只会中止自己的表演。顺手修掉了一个老问题：
  以前一个玩家退出，会把其他玩家的演员一起清掉。
- 网络改成单向注册并做版本隔离，新增服务端结束通知，客户端的清理也归到一个入口。
- 低 TPS 下请求会重试；调试用的第五阶段是无奖励预览。

## 兼容与边界

- 台词、理智阈值、触发所需的静止时长、攻击和掉落数值、5/20/60 tick 的转场，都保持原样。
- 新增两条限制：交互必须在演员 16 格内，抚摸至少要 60 个服务器 tick。远离演员会中止会话。
- 客户端和服务端必须用同一轮构建；紫怪协议版本 `purple-story-2` 与旧版本隔离。
- 旧的空载荷领奖消息，只能结算已经进入第五阶段的当前会话，不再是独立的发物品入口。
- 命名牌的旧 Python 时长测试脱节、怪树恢复、配置拆分，都留到后面。
- 不推送、不发布，所有改动留在工作区等审阅。

## 复验与游戏内建议

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/mcreator-guard/guard.ps1 -Action check
.\gradlew.bat test build --console=plain --offline
```

隔离开发专服的检查，可以加 `-I architecture/dedicated-smoke.init.gradle`。
不要用 Gradle 的 `--args="--nogui"` 覆盖 DevLaunch 主类的参数。
开发模式可能直接启动测试世界，就算 EULA 文件是 false 也一样，
所以要确保控制台可用并正常发 `stop`，别误用正式存档。
这次非交互的控制台没法写 stdin，所以用了只放在聊天 `work/` 里的临时诊断 helper 来正常停服，
没有把诊断 agent 放进模组或日常启动配置。

游戏内建议验证：

1. 自然触发或 `/purplegui 1` 走完整个流程，确认两个结局和一次性奖励。
2. 两个玩家同时表演，其中一人退出、死亡或换维度，另一人不受影响。
3. 在转场的各个时间点退出，演员不残留，客户端相机和输入不会被锁住。
4. 低 TPS 下完成抚摸后重试，能正确收到第五阶段通知，主手只丢一次。
5. 第五阶段预览能打开，但点击不发触手，也不写同化状态。
6. 用旧客户端连接，应报协议不匹配，不能悄悄进入混用状态。
