# 0001：延迟任务和理智同步状态由服务器会话持有

日期：2026-10-06。状态：第一轮已实施，验证结果见 `../ROUND-1.md`。

## 背景

生成的主类里有一个进程级的静态任务队列，停服时不会清理。理智的变化只写进缓存，没有任何发送调度。
玩家和世界对象被延迟回调捕获，退出或切换存档之后，这些引用可能一直留着。

## 决定

- `runtime/ServerTasks` 负责接入 NeoForge 的生命周期：每次 ServerStarting 新建一个
  `ServerTaskQueue`，ServerStopping/Stopped 时关闭并释放引用。
- 队列只由当前服务器线程操作。非当前服务器线程、或停服之后排进来的请求不会执行；
  对非服务端调用的忽略行为保持不变。取消接口会返回是否还有待执行的内容。
- `McanomalyarchivesMod.queueServerWork` 只保留为兼容委托，自己不再持有任何任务状态。
- 普通任务的计时方式不变：下一次 Post tick 采纳，再加 delay；回调里新排的任务，下一 tick 才采纳。
  到期时间相同的任务，按排队顺序执行。任务抛异常会写日志，不影响其他任务，但 Error 不会被吞掉。
- 玩家专属任务按 UUID 归属，退出或 Clone 时自动取消；执行前要确认玩家实例没被替换、
  仍然在线且存活。和玩家无关的世界任务，不会因为某个玩家退出而被取消。
- `DirtyPlayerSanityTracker` 自己订阅服务器和玩家事件，持有一个会话内的 `SanitySyncQueue`。
  同步队列只记 UUID，发送时才读理智值，每 5 tick 合并发一次。
- 登录和 Respawn 立即发送，并淘汰旧的待发记录；死亡后的数值重置，仍由原来的 Clone 逻辑负责。
- 理智的瞬态恢复计数在退出和 Clone 时清理，冷却记录在退出时清理，停服时全部清空。
- 故事自己持有会话标识和可取消的继续任务，停止后旧回调不能推进下一次故事。
  NPC 的故事在切换维度时中止；取消玩家任务，不会连带取消与它无关的世界任务。

## 模块与验证

`ServerTaskQueue` 和 `SanitySyncQueue` 都是真正在运行的策略实现，JUnit 直接从同样的接口测试它们，
没有复制一份公式，也没有为了单一用途引入通用框架。NeoForge 的接入靠守卫检查和编译来校验，
这并不等于验证了真实服务器的事件顺序，游戏内测试需要另外记录。

## MCreator 的限制

MCreator 重新生成时，可能把模板里的静态队列恢复回来，也可能覆盖兼容方法和 Gradle 的测试接线。
新增的守卫会拦住这种状态，不让它进入安全构建。委托方法可以从 canonical 恢复方法体，
但旧模板里的字段和 tick 属于 noMatch，要按提示手动移除；不会整文件覆盖主类。

这一轮保留了注册名、资源、理智数值和剧情台词，不改掉落或攻击数值。
复杂玩法的持久恢复、紫怪奖励权限、客户端与服务端配置，都留给后面的几轮。
