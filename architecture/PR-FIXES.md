## 发现的问题与复现

自检时在真实世界里复现了两个问题：

1. 世界建造上限 Y=320 处的写入返回 false，但恢复函数却返回 true，
   模块随后把唯一的快照消耗掉了。
2. `State="not-snbt"` 这样的记录，在被隔离之前就被改成了 RECOVERING，
   blocked 还是 false，原来的 journal 被重写。

修复前先补了会失败的回归测试：

```powershell
.\gradlew.bat test --tests net.mcreator.mcanomalyarchives.anomaly.strangetree.StrangeTreePlacementTest `
  --tests net.mcreator.mcanomalyarchives.anomaly.strangetree.StrangeTreeNbtTest `
  --console=plain --offline --no-build-cache
```

旧逻辑下，17 项里有 7 项失败（3 项写入确认，4 项损坏状态验证）。
提取写入 seam 时，刻意保留了“忽略返回值”的旧逻辑，用来确认测试确实能抓住它，之后才修正。

## 怎么修的

- `StrangeTreePlacement` 成了生产代码调用世界的写入和撤回接口。测试 adapter 可以真的拒绝写入，
  不用再复刻一套恢复算法。
- 整棵树先预检边界、高度和区块；每次写入必须被接受，并且读回的状态要匹配。
  写入抛运行时异常，也算失败。
- 每块写入前先记下完整的尝试索引，只有原来是空气的位置才算进撤回范围；
  前一块的回调如果改了后一块，会重新检查。
- 迁居失败后，要把已尝试、且仍是预期树块的位置撤回。被拒绝、抛异常或区块未加载时，不清 journal，
  下一次恢复会接着清目的地，不会先恢复原树，造成两棵树。
- 写入意图存进实体 journal 的 `PlacementUndo`，版本升到 2。旧的版本 1 仍能读，
  新字段没有塞进版本 1，免得旧构建悄悄忽略它。
- 撤回成功，计划才会被清掉；原位恢复成功，`finishStanding` 才消费树身快照。
- NBT 解析对 SNBT、Name 和字段类型做严格校验；世界 adapter 用真实的注册表和 Property 定义，
  检查未知属性和取值范围，模块通过这一关，才能 `recoverAfterLoad` 并写回。
- 校验失败走原有的隔离分支：保存原始 journal，只警告一次，不进入恢复重试循环。

## 世界回归

在独立的空服 `run/tree-smoke` 上跑，用本机临时端口和绝对 worlds 根，没碰正式存档。
诊断 helper 只在聊天 work/ 里，不进模组 jar。

实际检查了 7 项：

1. 原来的 Y=320 写入返回 false，restore 也返回 false，journal 保留。
2. 非法 SNBT：blocked=true，带 marker 的原记录完整保留。
3. 不存在的方块名、或非树方块：同样被隔离。
4. 怪树树干上有未知的 axis 属性：同样被隔离。
5. 怪树叶上有未知的 persistent 属性：同样被隔离（自定义方块本身没有这些属性）。
6. 通过生产写入接口，在真实世界里注入“第二次写入 false、首次撤回 false”。
   两次尝试的索引都先存了下来，目的地残留的树块没有被当成已完成。
7. 经过真实的 Entity.saveWithoutId 和 load 之后，生产模块先清目的地，再还原原树，
   目的地后来放的石头保留，只有恢复成功才消费 journal。

注入的拒绝作用在真实世界 adapter 的接口上，并不表示自然生成时模组一定会遇到任意的写入拒绝。
演员和测试位置都已还原，正常 halt 停服并保存成功。开发模式跳过 EULA 检查，文件保持 false。
