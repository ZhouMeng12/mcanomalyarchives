异域钓获与命名牌：模型、材质及功能详细方案

日期：2026-10-25。交付状态：八套模型源文件、十一种基础像素材质、八张独立 UV 材质、本地 HTTP 交互演示与本方案。本轮尚未修改游戏玩法代码；演示不是游戏已实现功能。

一、已确认的方向

钓获越远越诡异；异常主要体现在钓上来的生命与物品。保留现有致命事件概率，不默认增加新伤害。命名牌保留原轮廓、强化局部异化，本次明确加入缓慢吸收与压缩爆炸的设计和动态演示。黄金羊按视频抽帧调整：先异化脸与小腿，白色羊毛躯干不镀金，最后淡出显空腔。此前要求“强度变化先问”仍有效。用户本轮后续已明确：爆炸保持原触发时机，外观增加压缩；生物材质参考原版模型细化。

二、六档钓获

距离依据仍是实际浮漂与玩家距离；不伪造一个真实存在、可传送进入的新维度。现有异常度近似 clamp((距离-2)/13 + 随机扰动,0,1)，以下区间是视觉与内容设计档位，不是已经批准替换的概率表。

档位建议异常度模型与材质行为设计同源物品
1 近岸0–0.18红鳍异鱼：鱼身、深红鳞片、苍白眼、骨色背鳍入水游动、出水挣扎；鳍偶有反向摆动异色鳞片、红色水草
2 异域草甸0.18–0.35蒲公英牛：牛体、苔色皮肤、背部立体花茎花茎随呼吸移动、吃草、受惊躲避陌生花、带刺植物
3 荧海0.35–0.52荧光行足：粉色躯干和八条触腕，保持原版鱿鱼主体轮廓；不画眼睛、核心或触腕尖装饰水中游动，上岸触腕撑地寻找水；退缩避人荧光果实、黏性残留
4 褪色地带0.52–0.70白色末影人：苍白表皮、晶化骨架、肋骨缺口瞬移留晶尘、表皮缓慢剥落；敌对规则保持基础末影人逻辑透明鳞片、白色结晶
5 深界0.70–0.86不明残肢：断面、骨芯、第二层关节、方向不一致的指节弱收缩、向不存在的主体靠拢；默认不新增攻击黑色组织、异常金属
6 远界0.86–1折叠空壳：偏斜框架、内部悬浮组织、不同平面的骨条外框与内部组织不同步转动；不附加窥视即死空壳、时空漂流瓶、记录碎片

相邻档位交叉出现，避免抛远一格就彻底换生态。建议采用五分之一左右档位宽度的过渡带；正式概率表需要在替换当前池前列出。现有高异常致命事件先判定，普通钓获路径再选择内容，不额外增加第二次致命抽奖。替换现有 Boss 池会改变实际难度，不能假称纯外观改动。

同一水域以世界种子、维度 ID、区域坐标生成稳定生态主题。水域内物品与生物共享颜色、组织结构和残留物；这比随机混合下界矿物与普通动物更能建立异维度来源。主题不在游戏内显示“等级/危险值”面板。

三、资产交付与游戏接入

目录：previews/anomaly-lab/assets/。

  • specimens.json：八套部件模型，位置、尺寸、欧拉角、材质 ID；单位 1/16 格，Y 向上。
  • redfin / bloomcow / walksquid / pale / remnant / fold / sheep / stick.bbmodel：Blockbench free 模型源文件，每个嵌入材质图集，可继续调整部件和骨骼。
  • specimen-atlas.png：176×16 基础材质图集；另有每只生物/试体的独立 128 像素宽 UV 图，按面分配头、身、腿、触腕、角与附生结构。十一张基础色材质仍可单独重绘。
  • generate_assets.py：固定随机种子的可重复生成脚本。

这些为第一版真实几何和像素材质资产，不是实体已注册、Java 模型已导出的声明。第二版已拆为八套专用 UV，参照本机 Minecraft 1.21.1 客户端中的牛、羊、鱿鱼、末影人原版贴图结构，保留皮毛斑块、面部和触腕的像素组织，重新配色并叠加异常结构。原版参考存放在 assets/reference，仅用于本地模组设计。鱼与远界组织使用专门绘制的鳞片、断面和骨质图案。正式游戏仍需将伤口、裂纹、发光区域接成可控材质层。半透明触腕、折叠结构遮挡和发光层需要 Minecraft 渲染验证；网页里没有冒充真正发光着色器。

接入顺序：独立注册新 ID → 导出 LayerDefinition/ModelPart → 定义碰撞箱 → 实体与动画状态 → 渲染器与独立纹理 → 服务端钓获表 → 同步及跟踪补包。旧实体、旧物品 ID 不改名。视觉漂浮不直接改变碰撞与飞行能力。生命、基础伤害、掉落和跨区块寿命逐项列出后确定。

四、命名牌：缓慢吸收

现状与缺口

当前 EntityNaming.seizeNearby 已有水平 ±32、垂直 ±24 的扫描，每 20 tick 处理最多 96 列，目标上限为一个方块量。现有实现进入单列、单容器和整组掉落物后没有按剩余容量停止，可能一次吞掉超额物资；掉落物还存在整组移除、记账不按整组一致处理的问题。当前吸收只有泛用烟雾，没有实际来源到身体的传输过程；结束时身体被替换成方块，需按保留轮廓的选择改造。

推荐时序

  • 接管，0–10%：原轮廓保留，失去自主移动；眼部、蹄部先有小块金属斑，低频金属鸣响。
  • 吸收，10–40%：从已成功扣除的材料位置产生细小金属颗粒，沿短弧线汇入身体；不给未扣除的箱子或矿物播放虚假吸收。网页的来源方块为演示道具，不代表拟新增“必须摆四块”的规则。
  • 侵入，40–75%：固定空间分布的斑块扩大，面部与四肢先固化；哭泣、局部抽搐，声音逐渐失去生物质感。
  • 固化，75–100%：保留羊的头、腿与轮廓；羊脸和小腿局部金斑扩散，白色羊毛躯干不转成金色；末段将整体材质层淡出以显出中空感。网页按采样帧时序做近似预览，不能代替游戏透明渲染。

时长先沿用现有 15–120 秒公式；羊→金块按当前计算约 65 秒。网页约 11 秒，支持拖动进度，不能视为游戏实际时长。游戏里不加解释性 HUD 或进度条。

吸收结算

  • 使用统一材料点账：一方块 81、锭/宝石 9、粒 1。所有材料来源共享剩余额度 max(0,81-已吸收)。
  • 容器逐槽按可容纳的完整物品数量扣除；地面物品减少数量，余量留在原地，不整组丢弃。装备只能作为不可拆分物品按既有材料规则判断，不在本轮发明返还碎片。
  • 方块只能整块扣除。额度不足以容纳整块时跳过，不超扣；矿物使用对应石质替换规则，不额外产出矿物掉落。
  • 扣除成功才记账，记账成功才发送表现包；不先播粒子再尝试扣物。
  • 为避免一次扫描数千方块，将现有每秒扫描总预算摊到每 tick，而不是增加总扫描量；单个实体与全服都有预算，使用公平轮转。
  • 仅扫描已加载区块，限定所属维度，不强制加载；跨维度、实体销毁、卸载停止任务。容器扣量只在服务端执行；多人同一 tick 依次扣除，不能双花。
  • 保留现有“不足材料也会完成”的规则。把材料不足改为爆炸会扩大惩罚，不能暗中加入。

完成形态：需确定的玩法参数

推荐固化后保留原生物形状的静态金属壳；是否可击碎、掉落多少、能否挪动，会影响资源与实体数量。当前“完成后放置一个目标方块”的玩法需要迁移，不能只改渲染就宣称已解决。建议后续以独立雕像实体承载，限制重复命名；明确确认掉落规则后再接入。

五、命名牌：压缩爆炸

适用对象

演示示例为木棍→钻石块，表现来自参考视频中的跨类质料冲突。不是所有命名都爆炸，不让正常吸收不足自动触发。正式接入前先审计现有跨类失败入口，复用同一失败判断；本轮不自行新增“长名字/昂贵名字必爆”的规则。

时间与表现方案

阶段演示时序可观察变化服务端动作
冲突0–25%原物保持形状，少量目标材料碎屑闪现固定目标 UUID、失败原因、结算位置；禁止重入
压缩25–75%主体逐渐缩到约原来 12%，周围粒子向内卷，低鸣升高只同步过程，不产生吸力伤害，不移动玩家
临界75–90%裂纹变亮，压缩停止，短促尖鸣即将结算标记，不额外增加致盲、强制视角
释放原游戏判定时刻；网页 90% 后单次碎裂、外扩冲击环、少量残渣沿用现有质料差额决定的威力，上限 6.0；沿用现有地形破坏设置，不连续二次爆炸

用户已选择不增加 4 秒预兆。原有服务端爆炸条件成立时仍立即结算，不等待压缩动画完成。 网页为了看清过程而慢放，百分比不映射新增游戏等待。游戏中可在已有不稳定物品存续期间表现微缩、裂纹与向内粒子；如触发前没有可用时间，只在触发瞬间播放快速收缩与释放，不事后伪造可躲避预警。冲击环不代表额外伤害半径。

结算与持久化

服务端保留原有不稳定标记及爆炸触发判断；表现使用 CONFLICT → COMPRESSING → CRITICAL → RESOLVED 状态，不让视觉状态成为新的伤害计时器。存储过程 ID、源实体 UUID、目标注册 ID、维度 ID、开始游戏刻、持续时间、既有失败原因、原威力参数、是否已结算。客户端只依据状态渲染，不根据粒子碰撞决定伤害。

不新增为了播放动画而强制锁定物品、禁止拾取的规则。优先在原有不稳定 ItemStack 的身份、存续和触发路径中附加表现；视觉变形不改变使用手感或原触发条件。需验证拆堆、拾取、换手、丢弃、再次命名不会产生重复产物。客户端只呈现源模型变形。结算前标记已处理，按一次性事务移除源物、结算既有爆炸与既有残渣。这里要对现有产物顺序做审计，不能凭空保证崩溃时严格一次。

进程随所属维度保存，不保留跨世界静态任务。卸载与重载沿用原物品触发规则，不新增自动倒计时；视觉重建依据当前不稳定状态，销毁原因与管理员移除要区分，阻止复制。旁观玩家加入跟踪需补发当前进度。声音按阶段播一次，不因补包重复尖鸣。

六、实现分步与验证

  • 本轮已交付：八套几何源模型、材质图集、可旋转缩放预览、吸收与压缩爆炸时序演示、详细方案。
  • 下一步外观接入：撤回目标生物模型替身，保留原模型；实现稳定斑块、分层金属壳、来源粒子。至少验证羊、牛、猪三类骨架。此步不承诺所有视频实验一次实现。
  • 吸收修正：纯 Java 剩余额度与扣量策略测试；逐列、容器、掉落物统一上限；检查多实体公平预算。金属壳结局需确认产物规则。
  • 压缩状态机：复用现有失败入口；保持原触发时机并附加压缩视觉，接上单次原威力爆炸，验证重登、换维、重复触发、堆叠、卸载、跟踪补包。
  • 钓获接入：先确定普通池替换权重和新生物属性，再注册和接入；现有高异常事件概率保持独立，不重复抽取。

玩法改动前按工程约定提交本地基线。完成后运行真实 Java 单元测试、MCreator guard 与离线构建；这些不能替代 Minecraft 客户端验证。当前环境无法运行游戏，模型层级、透明排序、动画、实际音效和多人场景均须游戏内验收。
