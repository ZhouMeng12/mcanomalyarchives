# UO-008 实体转化设计（被命名的生物会慢慢变成对应的生物）

> 作者要求：**被命名的生物会慢慢变成对应的生物**。
> 本文是这套机制的设计稿；配套：玩法方案 `uo-008-name-tag-plan.md`、技术实现 `uo-008-naming-mechanics.md`。

---

## 0. 这条要求推翻了什么

现在的实体侧是"**角色扮演**"：牛被命名成"鸡"之后，我们只在它身上叠了一层行为覆盖层
（下蛋、鸡叫、不能挤奶、按寿命计次死亡），**它始终还是那头牛**，永远不会变成鸡。

新要求改成"**真的转化**"：生物会沿一条时间轴推进，最终**本体换成目标事物**——
目标生物、目标方块、目标物品都算。

---

## 1. 设定依据（正片其实两种都演过）

| 正片桥段 | 观测到的事实 | 支撑哪种设计 |
|---|---|---|
| 【旁白 1:30-1:42】牛 →「鸡」 | "命名后并没有发现任何明显的转换现象"，但**不能挤奶了**、发出鸡的怪叫、开始下**牛蛋** | 行为**立刻**接管，外形**不立刻**变 |
| 【旁白 1:47-2:00】同一头牛 | 开始不停撞墙、发出惨烈的悲鸣；用普通命名牌改回去**失败**；多次产蛋后**在痛苦挣扎中猝死** | 转化过程是**痛苦且不可逆**的；且**不保证能完整走完** |
| 【旁白 3:47-4:36】羊 →「金块」 | **不是瞬间**：先是失去活性、躯体僵硬，然后**部分身体慢慢被金子取代**，期间**眼里流出泪水**，附近含金设备零件缺失，最终**整个躯体被替换、内部完全中空** | 转化有**漫长过程**，过程中**保留意识**，且**要从环境掠夺材料** |

**结论**：正片给出的就是"**慢慢转化**"——行为立刻变、外形慢慢变、最终本体被替换。
新要求正好把它补齐。

---

## 2. 统一模型：命名 = 给生物挂上一条转化时间轴

```
被命名
  │  0%  ── 行为立刻接管（现在就有的那一层：音效身份、能不能挤奶/剪毛、产出）
  │ 25%  ── 开始"不适"：抽搐、粒子、惨叫；原版特征逐项失效
  │ 50%  ── 体型向目标推进（可观测的"变"）
  │ 75%  ── 材质化的迹象：身上出现目标材料的痕迹（粒子/音效）
  └ 100% ── 完成：本体替换成目标
```

**三种目标，三种终局**：

| 名字指向 | 完成时发生什么 | 现状 |
|---|---|---|
| **生物** | 原地替换成**那个生物的真身**（真 AI、真掉落、真音效） | 现在只叠行为层，**要新写** |
| **方块** | 躯体变成那个方块（正片羊→金块） | 已有（掠夺式延迟转化），改接到这条时间轴上 |
| **物品** | 躯体析出那个物品（按质料守恒折算数量） | 已有（即时），改成在时间轴末端发生 |
| **覆盖表**（无/地球/乱码/土豆） | 各自的专用结局（抹除等） | 已有，保持不变 |

---

## 3. 为什么"替换成真生物"是最优解

替换成真的 `Chicken` 之后，**现在靠打补丁实现的东西全部自动正确**：

| 现在要手写 | 替换成真鸡之后 |
|---|---|
| 每 120 tick 手动生成"牛蛋" | 生成本就是鸡的行为 |
| 靠 `PlayLevelSoundEvent` 把牛叫换成鸡叫 | 它自己就是鸡叫 |
| 手动拦挤奶 | 鸡本来就没奶 |
| 手动算"寿命归零就死" | 由转化完成取代 |
| 掉落表还是牛的 | 掉落表自动变成鸡的 |

也就是说：**这条机制会把实体侧的一堆积木替换成一个更简单的模型**——
"转化进度"取代"寿命计数"，"真身替换"取代"行为覆盖层"。

## 4. 时间轴细节

### 4.1 转化时长

按作者"慢慢"的要求，且要让"越离谱的名字越慢"成立（2026-09-13 又要求"快一点"，已整体压缩）：

```
durationTicks = clamp(名字字符数 × 100 + 质料差额 × 1, 300, 2400)   // 15 秒 ~ 2 分钟
```

| 例子 | 时长 |
|---|---|
| 羊 →「石头」（质料刚好够） | 撞下限，**15 秒** |
| 羊 →「铁块」 | 1 分 39 秒 → **约 20 秒** |
| 羊 →「钻石块」 | **约 26 秒** |
| 羊 →「金块」（正片那一段） | 4 分钟 → **约 65 秒** |

（公式与阶段划分有离线自检：`tools/nametag/test_transform.py`；
想要新时长表就跑 `tools/nametag/calc_transform_time.py`，它直接读 Java 里的常量与质料表来算。）

### 4.2 夺取材料（作者 2026-09-13 定的规则）

**"周围 64×64 范围内有金子就夺取，没有就算了，但还是要换。"**

- **范围**：水平 ±32 格（64×64 的面积）、上下 ±24 格。逐**列**推进（游标存进 persistentData 循环），
  每 20 tick 扫 96 列，4096 列一轮 —— 不会一次扫完卡主线程。
- **怎么夺**：金块一类**直接消除**；金矿**变成石头**（深层金矿变深层、下界金矿变下界岩）；
  地上的同类掉落物、以及沿途容器里的同类物品**一并没收**。
- **同类材料靠"材料族"判定**：金 / 铁 / 钻石 / 下界合金 / 绿宝石 / 铜 / 煤 / 青金石 / 红石各一族，
  装备用 `Tiers.GOLD`、`ArmorMaterials.GOLD` 这类材质直接认（金镐金剑金甲一整族）。
- **它不是完成条件**：时间到就一定换。掠夺只是"代价与演出"，
  所以不会再出现"卡在 100% 等材料"的情况（正片里那个"设备零件缺失"仍然保留）。

- **质料不够时不会爆炸**（爆炸是"物品被命名"那一支的规则）：生物能拖，靠**从环境掠夺材料**慢慢补，
  掠夺不到就**卡在 75% 不动**（对应正片羊一直没能完成、最后靠设备零件凑齐）。
- 时长参数全部可调。

### 4.2 各阶段的可观测表现

| 进度 | 表现 | 行为影响 |
|---|---|---|
| 0% | 无 | **立刻**接管：音效身份、挤奶/剪毛由名字决定、目标产出开始 |
| 25% | 抽搐、烟雾粒子、悲鸣音效 | 原生物独有产出失效（牛不再产奶） |
| 50% | 体型向目标体积收缩/膨胀 | 移动速度向目标靠拢 |
| 75% | 目标材料粒子（羊身上掉金粒） | 若质料不足则**卡在这里**，持续从环境掠夺 |
| 100% | 原地替换 | 真身接管一切 |

### 4.3 完成时的替换细节

- **保留**：位置、朝向、自定义名（玩家写的那个名字）、被命名标记（不可逆）、
  以及"这条转化记录"（便于以后做图鉴/成就）
- **不保留**：血量（新个体满血）、原生物的掉落（**它不是死了，是变成了别的**）
- **全程不可逆**（正片明确："用普通命名牌改回去失败"）

---

## 5. 会跟已有规则打架的地方

1. **"外观不变"**：那条规则是给**物品**定的（作者原话在物品语境里）。
   生物走的是"慢慢变成"，所以**生物不适用"外观不变"**——这是本文最需要拍板的一点，见 §7。
2. **"寿命 = 名字字数"**：被转化进度取代，`NameTagCosts.lifespanFor` 退役。
   （正片里牛确实死了，但那是"转化没走完"的表现，可以做成"卡在 75% 太久也会衰竭而死"。）
3. **材料析出（物品名）**：现在命名瞬间就析出，改成时间轴走到 100% 才发生。
4. **`EntityTickEvent` 负载**：现在是每 5 tick 处理一次，加了进度推进后负载不变
   （仍是一个除数判断 + 一次 NBT 读）。

## 7. 需要拍板的三点

### 甲 / 乙：转化期间看不看得见"变"

- **方案甲（贴合正片、便宜）**：期间外观**完全不变**（正片原话："并没有发现任何明显的转换现象"），
  只靠粒子/音效/抽搐暗示；到 100% 才**整体替换**。
  代价：玩家会觉得"怎么突然就变了"。
- **方案乙（看得见、贵一点）**：期间**模型随进度缩放到目标体积**——牛会一点点缩成鸡那么大，
  命名成末影龙则一点点涨大。
  代价：需要一个客户端 mixin（缩放 `LivingEntityRenderer`）+ 一个同步包（把进度发给附近玩家）。
  我们已经有 6 个客户端 mixin 和现成的网络通道，技术上不新鲜。

### 转化时长

- **随名字与质料变化**（推荐，见 §4.1）：越长、越"重"的名字越慢，天然形成压力。
- **固定时长**：可预期，但少了"越离谱越慢"的层次。

### 完成后的旧生物

- **不掉落**（推荐）：它是被转化了，不是死了。对应正片"羊变成金块"没有任何羊肉掉落。
- **按原生物掉落**：等于死了一次，会变成刷物品的漏洞（牛→鸡反复刷皮革）。

---

## 8. 边界（沿用已定的规则）

- 不作用于玩家；不作用于 Boss（凋灵/末影龙/监守者）；不作用于本模组的异常实体。
- 转化不可逆。
- 卡在最后一步（掠夺不到材料）时**不惩罚**，只是停在那——玩家得自己搬材料过去。
  （可选：卡太久后衰竭而死，对应正片牛的结局。）

## 9. 实现状态

作者拍板：**看得见（体型慢慢缩放）+ 时长随名字与质料 + 不掉落**，
并追加"**模型和材质会慢慢变（或者模型不变，材质慢慢变）**"。

### 已实装

| 项 | 落点 |
|---|---|
| 转化时间轴（进度/时长/阶段） | `anomaly/nametag/NameTagTransform.java` |
| 行为立刻接管 + 推进 + 阶段表现 + 完成 | `anomaly/nametag/NameTagTicker.java` |
| 完成时**真身替换**（保留位置/朝向/名字/标记、不掉落、清转化状态） | `EntityNaming.replaceWith` |
| 生物→方块 / 生物→物品 接到时间轴末端 | `EntityNaming.completeBlockConversion` / `convertToMaterial` |
| 进度同步（命名时 + `StartTracking` 补发） | `network/NamedTransformPacket.java`、`client/NamedTransformClient.java` |
| 体型缩放 + 颜色渐变 | `mixin/NamedTransformRenderMixin.java` + `client/NamedMorphClient.java` |
| 公式自检 | `tools/nametag/test_transform.py` |

**这一版实现的"慢慢变"= 体型渐缩/渐涨 + 颜色向目标主色靠拢**（作者给的第二个选项：
"模型不变，材质慢慢变"）。体型取自目标生物的碰撞箱高度（牛→鸡就是一点点缩下去）。

### 两个诚实的限制

1. **颜色是乘算**：顶点色乘以贴图，所以只能"变暗/偏色"，没法把暗的生物变亮。
   牛→末影人很明显，牛→鸡几乎看不出来。
   → 想两个方向都明显、而且"模型也真的变"，需要把**目标的模型也画一遍做交叉溶解**
   （在 `render` 的 TAIL 用 `EntityRenderDispatcher` 画一个未入场的替身，两边互补淡入淡出）。
   那一步需要看着画面调，建议先看这一版的效果再决定上不上。
2. **"爆炸"这条路对生物关闭了**：以前实体跨类命名会按质料结算、不够就炸；
   改成"慢慢变"之后，材料不够只是**停在最后一步之前持续掠夺**（正片羊→金块），不再爆炸。
   爆炸仍然保留给**物品被命名**那一支（正片木棍→钻石块）。

### 退役的东西

- **"寿命 = 名字字数"**（`NameTagCosts.lifespanFor`、`EntityNaming.spendAction`）：
  被转化时间轴取代 —— 生物不再是被命名几次就猝死，而是走完转化、变成目标。
  两者都标了 `@Deprecated` 并写明了原因。
- 实体侧的**跨类即时结算**（`EntityNaming.settle`）同样退役。

## 10. 三种终局形态（作者 2026-09-13 定的最终规则）

**核心变化：只有"变成方块"保留过程，另外两支都是命名瞬间完成。**

| 名字指向 | 时机 | 失去 AI | 外观 | 终局 |
|---|---|---|---|---|
| **方块** | **慢慢**（时间轴 30 秒~5 分钟） | 立刻僵住 | 身体材质与方块贴图**真正的交叉溶解** | 原地变成那个方块 |
| **物品** | **瞬间** | —（直接没了） | 不变（不用换材质） | 变成物品实体，可右键拿起、当正常物品用 |
| **实体** | **瞬间** | 立刻换掉 | **不变**（模型与材质都不动） | 用名字所指生物的 AI |

### 10.1 变成方块：失去 AI + 真正的贴图混合

- **失去 AI**：`EntityNaming.loseVitality` → `setNoAi(true)` + 停寻路 + 清水平动量。
  `Mob.isEffectiveAi()` 因此为 false，整个 `serverAiStep()`（感知/目标/寻路/移动）停摆，它僵在原地；
  重力与碰撞照常。正片依据【旁白 3:55-4:06】：羊被命名后"瞬间失去了所有生物活性、躯体僵硬"。
- **真正的贴图混合**（作者明确要求"弄两张贴图的真正混合"，并**去掉了体型缩放**）：
  `NamedTransformRenderMixin` 在 `model.renderToBuffer(...)` 之后**把同一个模型再画一遍**，
  第二遍贴图换成目标方块、顶点色 alpha 随进度 0 → 255。第一遍原版渲染完全不动。
  两遍叠起来就是"这块材质一点点盖满它的身体"。
  - 顶点色本来就带 alpha（`VertexConsumer.setColor(int)` 按 ARGB 拆），配 `RenderType.entityTranslucent`
    即可混合，**不需要自定义 shader**，也不需要把原版那一遍改成半透明（那会牵扯渲染类型与排序）。
  - 时机选在 `renderToBuffer` 调用之后：姿势栈里还留着这只生物的位移/旋转、模型也 `setupAnim` 过了，
    所以第二遍的位置与姿态与第一遍完全一致。
  - 贴图不存在（比如 `fire`）就整段跳过，不会出现紫黑方块。
  - ⚠️ **修过一个 bug**：`blendTexture` 原来在进度 `>= 1.0` 时返回 null（想表示"混完了"），结果
    进度一满、混合被关掉，贴图"啪"地弹回生物原本的材质，而它还要等到服务端把它替换成方块——
    玩家看到的就是"材质正常变化，到最后突然变回原样"。现在只要进度 > 0 就一直盖着，
    到 100% 时 alpha = 255，直到它真的变成方块为止。

### 10.2 变成物品：瞬间，可右键拿起

- **瞬间**：命名那一刻直接 `convertToMaterial`（它连"僵住"这一步都不需要）。
- 产物是货真价实的物品实体：拾取延迟 0、`setUnlimitedLifetime()`（它不是掉落物，是那只生物变成的东西，
  不该自己过期）、带 `FromTransform` 标记；**右键即可拿起**，收进背包后就是一件正常物品。
- 「土豆」保留正片的特殊演出（遗体长出土豆嫩芽）。
- **不换材质**（作者明确要求）。

### 10.3 变成实体：瞬间换 AI，模型材质不变

作者选的是**方案 A：保留本体、把行为目标整套换掉**（`EntityAiSwap`），
而不是换掉实体本体——因为换本体外观也就跟着变了，而要求是"模型/材质不变"。

- 原版大多数生物的行为就是 `goalSelector` 里那一串 Goal（外加 `targetSelector` 的攻击目标），
  而 `Mob.goalSelector` / `targetSelector` 都是 `public final`，可以直接清空重装。
- 被动动物按各家的 `registerGoals` 抄了一套模板（0 FloatGoal → 1 PanicGoal(速度) → 2 BreedGoal
  → 3 TemptGoal(速度, 食物) → 4 FollowParentGoal → 5 WaterAvoidingRandomStrollGoal → 6 LookAtPlayerGoal
  → 7 RandomLookAroundGoal），鸡/牛/羊/猪/兔/山羊/羊驼/马/龟/狐/猫/豹猫/狼/鹦鹉/美西螈/蜜蜂各有各的速度与食物；
  僵尸/骷髅/蜘蛛/苦力怕/末影人等攻击型生物装的是"追着玩家打"那一套。
- 于是：**牛被命名成"鸡"就会像鸡一样乱窜、被种子吸引、怕玩家；命名成"僵尸"就会追着人打。**
- **换不来的部分**：写在 `aiStep`/`customServerAiStep` 里的特有能力（鸡的下蛋计时器、羊的吃草）、
  掉落表、繁殖产物仍然是原生物的。下蛋由 `NameTagTicker` 补（正片那头牛就是靠这个下"牛蛋"）。
  要让掉落表也跟名字走，就得换本体，那是方案 B——作者选了"先做 A，不够再上 B"。
- 只支持 `PathfinderMob`：史莱姆、恶魂这类不走寻路目标的另有一套移动逻辑，Goal 装上去也没用。
